## Problem Statement & Scope
Diberikan berkas biner ELF dan kode sumber `chall.c` yang mendemonstrasikan kerentanan manajemen siklus hidup memori tingkat lanjut pada heap. Program mendefinisikan sebuah struktur objek:
```c
typedef struct {
  char a[10];
  char b[10];
  char c[10];
  char flag[5];
} object;

object *x;
```
Program mengalokasikan objek `x` di heap dan menginisialisasi string `x->flag` dengan `"bico"`. Program menyediakan opsi menu untuk membebaskan pointer `x` (`free(x)`), mengalokasikan memori baru dengan ukuran sembarang, dan memverifikasi kondisi kemenangan melalui `check_win()` yang memeriksa apakah `x->flag` bernilai `"pico"`.

Program menyediakan antarmuka menu berbasis terminal:
1. **Print Heap:** Menampilkan alamat dan nilai aktif pada memori heap.
2. **Allocate object:** Mengalokasikan blok memori dinamis baru sesuai ukuran yang ditentukan pengguna.
3. **Print x->flag:** Memeriksa nilai string yang tersimpan pada field `flag` dari objek `x`.
4. **Check for win:** Memvalidasi apakah `x->flag` bernilai `"pico"`. Jika cocok, flag dicetak.
5. **Free x:** Memanggil `free(x)` untuk mendealokasikan objek `x`.
6. **Exit:** Menghentikan program.

## Teori & Akar Kerentanan (Root Cause Theory)
1. **Dangling Pointer & Use-After-Free (CWE-416):**
   Fungsi `free_memory()` memanggil `free(x)` untuk membebaskan blok memori heap yang dialokasikan ke `x`:
   ```c
   void free_memory() {
       free(x);
   }
   ```
   Setelah fungsi `free()` dieksekusi, pointer global `x` tidak disetel ulang ke `NULL` (*pointer grounding* diabaikan). Akibatnya, `x` menjadi penunjuk menggantung (*dangling pointer*) yang masih mereferensikan alamat memori heap yang telah dibebaskan.
   Fungsi `check_win()` tetap membaca data dari `x->flag`:
   ```c
   void check_win() {
       if(!strcmp(x->flag, "pico")) {
           printf("YOU WIN!!11!!\n");
           // Membaca dan mencetak isi flag.txt
       }
   }
   ```
   Kondisi ini menimbulkan kerentanan Use-After-Free (UAF).

2. **Mekanisme Chunk Recycling pada Glibc Heap (tcache):**
   Ukuran `sizeof(object)` adalah:
   $$10 + 10 + 10 + 5 = 35 \text{ byte}$$
   Pada glibc malloc arsitektur x86-64, alokasi 35 byte ditempatkan dalam chunk berukuran 0x30 (48 byte). Saat blok ini dibebaskan dengan `free(x)`, glibc menempatkan chunk tersebut ke dalam antrean *thread-local caching* (tcache bin untuk size 0x30).
   Mekanisme alokasi memori glibc tcache bersifat *LIFO* (*Last-In, First-Out*). Ketika program meminta alokasi baru dengan ukuran yang sama (misalnya 35 byte) melalui fungsi `alloc_object()`:
   ```c
   char* alloc = malloc(size);
   scanf("%s", alloc);
   ```
   Pengelola heap mengembalikan alamat chunk yang sama persis dengan yang baru saja dibebaskan.

3. **Kalkulasi Offset Field Struktur:**
   Tata letak memori dalam struktur `object`:
   - `a[10]`: offset 0 sampai 9 (10 byte)
   - `b[10]`: offset 10 sampai 19 (10 byte)
   - `c[10]`: offset 20 sampai 29 (10 byte)
   - `flag[5]`: offset 30 sampai 34 (5 byte)

   Diagram visual tata letak memori struktur `object`:
   ```text
   +-------------------------------------------------------------------------+
   | Offset (bytes) | Field Name  | Array Size | Injected Content            |
   +-------------------------------------------------------------------------+
   | 0x00 - 0x09    | a           | 10 bytes   | "AAAAAAAAAA"                |
   | 0x0A - 0x13    | b           | 10 bytes   | "AAAAAAAAAA"                |
   | 0x14 - 0x1D    | c           | 10 bytes   | "AAAAAAAAAA" (30 bytes pad) |
   | 0x1E - 0x22    | flag        | 5 bytes    | "pico\0"                    |
   +-------------------------------------------------------------------------+
   ```
   Dengan menuliskan 30 byte padding (misalnya 30 karakter `'A'`) diikuti dengan string `"pico"`, memori pada offset 30 akan diisi dengan `"pico"`. Karena penunjuk `x` masih merujuk ke blok memori tersebut, dereferensi `x->flag` membaca string `"pico"` yang baru ditulis.

## Metodologi Pengujian NIST SP 800-115
Berdasarkan panduan NIST SP 800-115 (*Technical Guide to Information Security Testing and Assessment*):

1. **Fase Perencanaan & Penemuan (Planning & Discovery):**
   - Menelaah siklus hidup pointer `x` dari alokasi awal hingga deallokasi.
   - Mengamati ketiadaan pembersihan referensi pointer setelah fungsi `free(x)`.
2. **Fase Analisis Kerentanan (Vulnerability Analysis):**
   - Mengidentifikasi kelemahan CWE-416 (Use-After-Free) melalui keberadaan *dangling pointer*.
   - Menganalisis perilaku alokator glibc tcache bin yang menggunakan strategi alokasi LIFO.
   - Menghitung offset field `flag` dari pangkal struct: $10 + 10 + 10 = 30$ byte.
3. **Fase Eksploitasi & Verifikasi (Attack Execution & Verification):**
   - Mengirimkan perintah deallokasi (Menu 5).
   - Mengirimkan perintah realokasi (Menu 2) dengan ukuran 35 byte.
   - Mengisi buffer dengan payload 30 byte padding + `"pico"`.
   - Memicu evaluasi `check_win()` (Menu 4) untuk memvalidasi keberhasilan manipulasi memori dan mengekstrak flag.
4. **Fase Remediasi & Mitigasi (Remediation):**
   - Menerapkan pointer grounding segera setelah `free()` dan memanfaatkan allocator modern yang diperkeras.

## Takeaway Kompetensi LKS & Mitigasi Defensif
1. **Pentingnya Pointer Grounding Pasca-Deallokasi (CWE-416):**
   Praktik pemrograman defensif wajib menerapkan *pointer grounding* segera setelah memori dibebaskan:
   ```c
   free(x);
   x = NULL;
   ```
   Pemeriksaan kondisi `if (x == NULL)` pada fungsi akses mencegah eksploitasi dangling pointer dan menghasilkan *fail-fast crash* daripada pembacaan memori usang.
2. **Penggunaan Smart Pointers & RAII:**
   Pada bahasa modern seperti C++ atau Rust, manfaatkan prinsip RAII (*Resource Acquisition Is Initialization*) dengan `std::unique_ptr` / `std::shared_ptr` di C++ atau sistem kepemilikan (*ownership & borrow checker*) di Rust yang secara matematis menjamin pencegahan kerentanan Use-After-Free.
3. **Pendeteksian Dini via ASan (NIST SP 800-115 Testing Standards):**
   AddressSanitizer (`-fsanitize=address`) memantau status alokasi heap dan mendeteksi akses ke memori yang sudah di-free (*heap-use-after-free*) secara otomatis saat pengujian regresi biner.
