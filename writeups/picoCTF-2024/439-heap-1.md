## Problem Statement & Scope
Diberikan berkas biner ELF 64-bit dan kode sumber C (`chall.c`) yang mendemonstrasikan alokasi dinamis memori heap menggunakan glibc malloc. Pada tantangan lanjutan ini, peserta tidak hanya diminta merusak isi variabel pada heap secara acak seperti pada `heap 0`, melainkan harus mengendalikan isi luapan (*controlled buffer overflow*) agar variabel target `safe_var` bernilai tepat string `"pico"`.

Program menyediakan antarmuka menu berbasis terminal:
1. **Print Heap:** Menampilkan alamat memori dan data string aktif di heap.
2. **Write to buffer:** Membaca input pengguna ke dalam chunk `input_data`.
3. **Print safe_var:** Memeriksa nilai string variabel `safe_var`.
4. **Print Flag:** Memeriksa kondisi kemenangan melalui fungsi `check_win()`.
5. **Exit:** Menghentikan program.

## Teori & Akar Kerentanan (Root Cause Theory)
1. **Tata Letak Chunk Glibc Malloc pada Arsitektur x86-64:**
   Program memanggil alokasi memori berurutan pada fungsi `init()`:
   ```c
   input_data = malloc(INPUT_DATA_SIZE); // INPUT_DATA_SIZE = 5
   strncpy(input_data, "pico", INPUT_DATA_SIZE);
   safe_var = malloc(SAFE_VAR_SIZE);     // SAFE_VAR_SIZE = 5
   strncpy(safe_var, "bico", SAFE_VAR_SIZE);
   ```
   Pada glibc malloc arsitektur 64-bit, setiap alokasi berukuran kecil dibulatkan ke ukuran minimum chunk sebesar 32 byte (0x20 byte, mencakup 16 byte metadata chunk header/prev_size/size dan 16 byte user data payload). Karena kedua alokasi dieksekusi berturut-turut tanpa intervensi alokasi lain, kedua chunk ditempatkan secara berdampingan (*contiguous heap memory*).

2. **Kalkulasi Offset Antara Dua Chunk:**
   Alamat memori pengguna (*user payload pointer*) berjarak tepat 0x20 byte (32 byte desimal):
   $$\text{Offset} = \text{Address}(\text{safe\_var}) - \text{Address}(\text{input\_data}) = 0x20 = 32 \text{ byte}$$

   Diagram visual memori heap:
   ```text
   +-------------------------------------------------------------------------+
   | Address         | Chunk Content                    | Meaning            |
   +-------------------------------------------------------------------------+
   | 0x...000002b0   | 'p' 'i' 'c' 'o' \0 ... (padding) | input_data buffer  |
   |                 | [32 bytes total user chunk span] |                    |
   +-------------------------------------------------------------------------+
   | 0x...000002d0   | 'b' 'i' 'c' 'o' \0               | safe_var pointer   |
   +-------------------------------------------------------------------------+
   ```

3. **Ketiadaan Validasi Batas Input (`scanf("%s")` - CWE-122):**
   Fungsi `write_buffer()` membaca data dari terminal menggunakan penentu format tak terikat `%s`:
   ```c
   void write_buffer() {
       printf("Data for buffer: ");
       fflush(stdout);
       scanf("%s", input_data);
   }
   ```
   Fungsi `scanf` dengan `%s` membaca karakter tanpa batasan ukuran buffer penampung hingga mendeteksi karakter pemisah (*whitespace* atau *newline*). Ini menciptakan kerentanan CWE-122 (*Heap-based Buffer Overflow*).

4. **Kondisi Kemenangan Terkontrol (*Controlled Win Condition*):**
   Fungsi `check_win()` mengevaluasi kecocokan string:
   ```c
   void check_win() {
       if (!strcmp(safe_var, "pico")) {
           printf("\nYOU WIN\n");
           // Membaca dan mencetak isi flag.txt
       }
   }
   ```
   Eksploitasi menuntut penulisan string presisi: tepat 32 byte padding diikuti oleh string `"pico"`.

4. **Fase Pelaporan & Mitigasi (Reporting & Remediation):**
   - Mendokumentasikan akar masalah, PoC reproduksi mandiri, serta panduan hardening kode sumber.

## Takeaway Kompetensi LKS & Mitigasi Defensif
1. **Analisis Alinyemen dan Layout Heap (NIST SP 800-115 / CWE-122):**
   Peserta LKS Cyber Security harus memahami bahwa alokasi memori heap tidak ditempatkan secara acak dalam satu thread. Alokasi sekuensial yang berukuran kecil berada di arena yang sama dan berjarak kelipatan 16 atau 32 byte. Pemahaman alinyemen chunk esensial saat menghitung offset tanpa menebak-nebak.
2. **Mitigasi Masukan Tidak Terikat:**
   Ganti penggunaan `scanf("%s", buf)` dengan fungsi pembacaan berbatas ukuran aman seperti `fgets(buf, max_size, stdin)` atau penentu lebar format `scanf("%4s", buf)`.
3. **Penerapan Compiler Hardening & Sanitizer:**
   Kompilasi biner dengan flag proteksi modern `-D_FORTIFY_SOURCE=2` dan AddressSanitizer `-fsanitize=address` pada fase CI/CD pengujian aplikasi untuk mendeteksi out-of-bounds write seketika saat runtime.
