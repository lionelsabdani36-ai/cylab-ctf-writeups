# RPS (Challenge 293, Binary Exploitation)

- **ID:** 293 | **Event:** picoCTF 2022 | **Kategori:** Binary Exploitation | **Level:** Easy (diff 2, 200 pts)
- **Flag:** `academy{50M3_3X7R3M3_1UCK_9C84B2D3}` (terverifikasi live `POST /api/submissions/` -> `correct: true`)

## Skenario
Program rock-paper-scissors via netcat (lab on-demand, URL rotasi).
Menang 5x beruntun -> flag. Source `game-redacted.c` tersedia.

## Root Cause
Dua cacat di `play()`: (1) `srand(time(0))` di-seed ulang tiap ronde
(output `rand()%3` mudah ditebak); (2) cek menang memakai
`strstr(player_turn, loses[computer_turn])` — pencocokan SUBSTRING.
Input `rockpaperscissors` mengandung ketiga kata, jadi selalu "menang"
apapun pilihan komputer.

## Rekonstruksi
1. Launch instance (`PUT /api/challenges/293/instance/`), catat `nc host port`.
2. Tiap ronde: kirim `1`, lalu `rockpaperscissors`.
3. Setelah 5 menang beruntun, server mencetak flag.
   Otomasi: `python3 scripts/solve_293_rps.py <host> <port>`.

## Mitigasi
Bandingkan pilihan dengan kesetaraan eksak (enum), bukan substring;
seed PRNG sekali dan gunakan sumber acak kriptografis untuk logika game.

## Takeaway LKS
Pwn logika: baca predikat kemenangan sebelum menyusun payload;
`strstr` sebagai komparator adalah pola bug klasik yang mengubah
tebak-tebakan menjadi kemenangan deterministik.
