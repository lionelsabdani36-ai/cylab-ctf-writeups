## Problem Statement & Scope
Aplikasi web kalkulator pinjaman bank (ABC Bank Loan Calculator) menyediakan fitur evaluasi formula finansial online bagi nasabah. Namun, backend aplikasi menggunakan pemanggilan fungsi evaluasi kode dinamis Python `eval()` secara langsung pada input pengguna.
Deskripsi menyatakan:
*"ABC Bank's website has a loan calculator to help its clients calculate the amount they pay if they take a loan from the bank. Unfortunately, they are using an `eval` function to calculate the loan. Bypassing this will give you Remote Code Execution (RCE). Can you exploit the bank's calculator and read the flag?"*

Objektif pengujian (NIST SP 800-115 / OWASP Top 10 A03:2021-Injection / CWE-95 Improper Neutralization of Directives in Dynamically Evaluated Code):
Menganalisis mekanisme sanitasi dan filter ekspresi reguler pada parameter formula, menyusun teknik bypass filter karakter berbasis *dynamic string concatenation*, mengeksekusi *arbitrary file read*, dan memulihkan token flag `/flag.txt`.

## Teori & Analisis Arsitektur Kerentanan
1. **Insecure Dynamic Code Evaluation (`eval()` Sink):**
   Fungsi `eval()` pada Python mengevaluasi string input arbitrer sebagai ekspresi Python murni. Jika input pengguna diteruskan ke dalam `eval()`, penyerang dapat mengeksekusi fungsi bawaan (*Python built-in functions*) dan memicu eksekusi kode jarak jauh (*Remote Code Execution*).
2. **Keterbatasan Sanitasi Berbasis Blacklist:**
   Pengembang berusaha mengamankan fungsi `eval()` dengan dua lapis filter reaktif (sebagaimana terdokumentasi pada komentar TODO di sumber HTML halaman login):
   - *Keyword Blacklist:* Memblokir kata kunci sensitif tertentu (`os`, `eval`, `exec`, `bind`, `connect`, `python`, `socket`, `ls`, `cat`, `shell`).
   - *Regular Expression Sanity Check:*
     `r'0x[0-9A-Fa-f]+|\\u[0-9A-Fa-f]{4}|%[0-9A-Fa-f]{2}|\.[A-Za-z0-9]{1,3}\b|[\\\/]|\.\.'`
     Filter regex ini memblokir encoding heksadesimal (`0x..`), unicode escapes (`\\u....`), URL encoded bytes (`%..`), karakter path slash (`/` dan `\\`), path traversal (`..`), serta ekstensi berkas pendek bertitik (`.txt`, `.sh`, `.py` dilarang oleh pola `\.[A-Za-z0-9]{1,3}\b`).
3. **Flaw Analisis & Filter Evasion:**
   - Fungsi bawaan `open()` tidak dimasukkan ke dalam daftar hitam kata kunci.
   - Karakter terlarang `/` (ASCII 47) dan `.` (ASCII 46) dapat dibentuk secara dinamis saat runtime (*runtime character synthesis*) menggunakan fungsi built-in `chr()`:
     `chr(47) + 'flag' + chr(46) + 'txt'`.
   - Pemanggilan metode pembacaan berkas `.read()` memiliki 4 karakter alfanumerik setelah tanda titik (`read`), sehingga tidak memicu regex blacklist yang hanya mencocokkan 1 hingga 3 karakter alfanumerik (`\.[A-Za-z0-9]{1,3}\b`).
   - Hasil evaluasi ekspresi `open(chr(47)+'flag'+chr(46)+'txt').read()` dikembalikan secara langsung pada template respons web di dalam tag `<p>Result: ...</p>`.

## Takeaway Kompetensi LKS & Mitigasi Defensif
- **Eliminasi Penggunaan `eval()`:** Jangan pernah mengevaluasi input pengguna menggunakan `eval()`, `exec()`, atau fungsi penerjemah kode dinamis lainnya untuk kalkulasi matematika/finansial.
- **Safe Expression Parser (AST-based Parsing):** Gunakan parser berbasis Abstract Syntax Tree yang aman seperti `ast.literal_eval()` (untuk data primitif) atau pustaka parser matematis terisolasi seperti `simpleeval` atau pustaka SymPy dengan operator whitelist yang ketat.
- **Strict Input Whitelist:** Hanya izinkan karakter numerik dan operator aritmatika dasar (`[0-9+\-*/(). ]`). Jika terdapat karakter di luar whitelist (seperti huruf `[A-Za-z]`), tolak permintaan sejak awal (*fail-safe input rejection*).
- **Filesystem Isolation (Container Sandboxing):** Jalankan aplikasi web di dalam lingkungan *read-only root filesystem* dengan akun pengguna `nobody` / unprivileged user, tanpa menyimpan berkas sensitif di jalur filesystem lokal server web.
