## Deskripsi Skenario & Batasan Lingkungan
Halaman profil mengizinkan unggah foto profil ke `upload.php` tanpa validasi
tipe/ekstensi. Lab on-demand (`xebec.cylabacademy.net:<port>`), flag di `/root/flag.txt`,
hint resmi: sanitasi upload hilang + perintah `sudo -l` pasca-shell.

## Teori & Akar Kerentanan (Root Cause)
1. **Unrestricted File Upload (CWE-434):** server memanggil `move_uploaded_file`
   ke `uploads/` memakai `basename($_FILES[...]["name"])` mentah, tanpa
   allowlist ekstensi/MIME. File `.php` ikut tersimpan dan dapat dieksekusi
   karena direktori uploads satu vhost dengan interpreter PHP.
2. **Eskalasi via sudo permisif:** `www-data` memiliki `(ALL) NOPASSWD: ALL`,
   sehingga RCE langsung menjadi root tanpa eksploitasi kernel.

## Takeaway Kompetensi LKS & Mitigasi Defensif
- Allowlist ekstensi + validasi magic bytes/MIME di server, simpan upload di
  luar docroot atau nonaktifkan eksekusi PHP (`php_flag engine off`) di direktori uploads,
  rename acak tanpa ekstensi user-controlled.
- Terapkan least privilege: jangan berikan `NOPASSWD: ALL` ke akun service web;
  batasi `sudo` ke biner absolut yang dibutuhkan dengan argumen tetap.
- Modul latihan: uji batas validasi input (NIST SP 800-115) tiap endpoint
  multipart sebelum rilis.
