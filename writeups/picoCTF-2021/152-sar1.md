## Problem Statement & Scope
Halaman validasi flag (`index.html` + JS obfuscated + modul `.wasm`)
via `http://chatelaine.cylabacademy.net:<port>/`. Sama seperti SAR2 tetapi
modul menyimpan flag **plaintext** di data section (tanpa lapisan XOR).

---

## Teori & Akar Kerentanan (Root Cause Theory)
1. **Rahasia di artefak klien:** flag utuh tertanam di biner `.wasm` yang
   diunduh browser — ekstraksi string seketika membocorkannya.
2. **Obfuskasi loader:** JS `_0x...` menyembunyikan nama file WASM
   (`./JIFxzHyW8W`), tetapi DevTools/Network tetap menunjukkannya.
3. **Ekspor simbol informatif:** `copy_char`/`check_flag`/`input` memberi
   peta fungsi tanpa perlu dekompilasi penuh.

---

## Rekonstruksi Eksploitasi Step-by-Step
1. Launch instance (PUT `/api/challenges/152/instance/`); buka URL lab.
2. Unduh JS loader → temukan path WASM `JIFxzHyW8W`.
3. Unduh WASM (824 B); `strings` langsung memuat
   `academy{8c87cb4dcc87959c351f832e6a165296}`.
4. Solver: unduh WASM → regex flag → selesai (tanpa decode).

## Takeaway Kompetensi LKS & Mitigasi Defensif
- **Validasi server-side wajib:** flag/secret tidak boleh dikirim ke klien
  dalam bentuk apa pun (plain maupun terenkode lemah).
- **Alur forensik WASM:** Network → unduh biner → `strings` → `wasm2wat`
  bila perlu; cek data section sebelum membedah logika.
- **Defensive:** pisahkan logika cek lisensi/flag ke endpoint API dengan
  rate-limit; frontend hanya menampilkan hasil.
