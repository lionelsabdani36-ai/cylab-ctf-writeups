## Problem Statement & Scope
Halaman validasi flag (`index.html` + JS obfuscated + modul `.wasm`)
via `http://chatelaine.cylabacademy.net:<port>/`. Tombol Submit memanggil
`copy_char` per karakter lalu `check_flag`; hasil Correct!/Incorrect!.

---

## Teori & Akar Kerentanan (Root Cause Theory)
1. **Validasi di sisi klien:** logika cek flag (WASM) dikirim ke browser —
   rahasia apa pun di dalamnya dapat dibaca offline.
2. **XOR single-byte:** `copy_char` meng-XOR tiap byte input dengan `8`
   sebelum `strcmp` ke data section. Ciphertext + kunci keyakinan rendah
   (satu konstanta) = decodable tanpa brute force berarti.
3. **Obfuskasi JS ≠ proteksi:** string `_0x...` hanya menghambat baca cepat,
   nama ekspor WASM (`copy_char`, `check_flag`) tetap terlihat.

---

## Rekonstruksi Eksploitasi Step-by-Step
1. Launch instance (PUT `/api/challenges/131/instance/`); buka URL lab.
2. Unduh `Y8splx37qY.js` (obfuscated): impor `./aD8SvhyVkb` sebagai WASM.
3. Unduh WASM (864 B); `strings` menampakkan segmen data terenkode:
   `ikilmeqs:9?n8jijlim<=?98981jj:m>ik9j9;<iu`.
4. Byte-per-byte `^ 8` → `academy{217f0babdae45710109bb2e6ac1b134a}`.
5. Solver mengotomatisasi: unduh WASM → ekstrak string printable → XOR 8 →
   cocokkan regex flag.

## Takeaway Kompetensi LKS & Mitigasi Defensif
- **Jangan validasi rahasia di klien:** pindahkan cek flag ke server;
  WASM/JS hanya untuk UX, bukan enforcement.
- **XOR satu-byte bukan enkripsi:** butuh kunci acak seukuran pesan (OTP)
  atau cipher modern; konstanta kecil selalu kalah dari analisis strings.
- **Defensive:** anggap semua aset frontend publik; uji dengan `strings`
  + `wasm2wat` sebelum rilis.
