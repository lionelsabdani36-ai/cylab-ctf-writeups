## Problem Statement & Scope
Diberikan berkas assembly x86 `test.S`. Analis diminta menghitung nilai kembalian (return value) fungsi `asm3(0xcc000a09, 0xcdb0b591, 0xc1116756)` saat dipanggil dengan tiga argumen heksadesimal 32-bit. Format penyerahan token adalah nilai heksadesimal yang diawali dengan `0x`.

---

## Teori & Akar Kerentanan (Root Cause Theory)
1. **Konvensi Pemanggilan cdecl & Pemetaan Stack Frame:**
   - Pada arsitektur x86 IA-32, parameter fungsi cdecl dipush dari argumen paling kanan ke kiri: `arg3`, `arg2`, `arg1`, kemudian `call` mempush return address (4 byte), dan prolog mempush `ebp`.
   - Tata letak byte memori stack frame relatif terhadap pointer basis `ebp`:
     - `[ebp + 0x8..0xb]`: `arg1 = 0xcc000a09` (Little-endian bytes: `0x09, 0x0a, 0x00, 0xcc`)
     - `[ebp + 0xc..0xf]`: `arg2 = 0xcdb0b591` (Little-endian bytes: `0x91, 0xb5, 0xb0, 0xcd`)
     - `[ebp + 0x10..0x13]`: `arg3 = 0xc1116756` (Little-endian bytes: `0x56, 0x67, 0x11, 0xc1`)

2. **Dekomposisi Sub-Register & Operasi Bitwise x86:**
   - Register `eax` (32-bit) memiliki sub-register `ax` (16-bit), yang terdiri dari `ah` (high byte, 8-bit) dan `al` (low byte, 8-bit).
   - Pergeseran bit `shl ax, 0x10` menggeser register 16-bit sejauh 16 bit ke kiri. Seluruh 16 bit keluar dari register dan terisi nol, menyisakan `ax = 0x0000`.
   - Modifikasi langsung terhadap sub-register `al` dan `ah` secara mandiri membentuk kembali nilai 16-bit register `ax` sebelum dilakukan operasi XOR dengan dereferensi kata 16-bit `WORD PTR [ebp+0x12]`.

---

## Rekonstruksi Eksploitasi Step-by-Step
1. **Pemetaan Nilai Byte Parameter:**
   - `[ebp+0xb]` = `0xcc`
   - `[ebp+0xe]` = `0xb0`
   - `[ebp+0xf]` = `0xcd`
   - `WORD PTR [ebp+0x12]` = Little-endian 16-bit dari byte `0x12` (`0x11`) dan `0x13` (`0xc1`), yaitu `0xc111`.

2. **Tracing Instruksi Sekuensial:**
   - `<+3>: xor eax, eax` $\implies$ `eax = 0x00000000`.
   - `<+5>: mov ah, BYTE PTR [ebp+0xb]` $\implies$ `ah = 0xcc`, `al = 0x00` $\implies$ `ax = 0xcc00`.
   - `<+8>: shl ax, 0x10` $\implies$ `ax = (0xcc00 << 16) & 0xffff = 0x0000`.
   - `<+12>: sub al, BYTE PTR [ebp+0xe]` $\implies$ `al = (0x00 - 0xb0) & 0xff = 0x50` (80 desimal). `ah` tetap `0x00` $\implies$ `ax = 0x0050`.
   - `<+15>: add ah, BYTE PTR [ebp+0xf]` $\implies$ `ah = (0x00 + 0xcd) & 0xff = 0xcd`. `ax = 0xcd50`.
   - `<+18>: xor ax, WORD PTR [ebp+0x12]` $\implies$ `ax = 0xcd50 ^ 0xc111`:
     - Byte tinggi: `0xcd ^ 0xc1 = 0x0c`
     - Byte rendah: `0x50 ^ 0x11 = 0x41`
     - Gabungan `ax = 0x0c41` = `0xc41`.

3. **Verifikasi Eksekusi Assembly Standalone:**
   Menyusun kode x86 standalone dan menghubungkannya via `as --32` dan `ld -m elf_i386` memverifikasi secara langsung pada kernel Linux bahwa nilai register kembalian adalah `0xc41`.

## Takeaway Kompetensi LKS & Mitigasi Defensif
- **Takeaway LKS:** Peserta LKS Cyber Security dituntut menguasai interaksi sub-register x86 (EAX, AX, AH, AL) dan representasi little-endian pada stack, terutama saat menganalisis biner malware atau algoritma enkripsi kustom yang mengandalkan manipulasi bitwise langsung.
- **Mitigasi Defensif:** Pengembang sistem tingkat rendah harus menghindari perilaku ambigu seperti bit shifting yang melebihi ukuran register native (undefined / implementation-defined behavior pada standar C/C++) dengan selalu memvalidasi batasan pergeseran bit (`shift amount < sizeof(type) * 8`).
