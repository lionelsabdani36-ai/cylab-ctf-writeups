## Problem Statement & Scope
Diberikan berkas assembly x86 `test.S`. Peserta diminta menentukan nilai kembalian fungsi `asm1(0xb70)` saat dipanggil dengan parameter heksadesimal 32-bit `0xb70`. Penyerahan token menggunakan representasi heksadesimal diawali dengan `0x`.

---

## Teori & Analisis Arsitektur x86 IA-32
1. **Pemeriksaan Kondisi Branching:**
   - Parameter fungsi berada pada `[ebp+0x8]`.
   - Instruksi `cmp DWORD PTR [ebp+0x8], 0x6af` diikuti `jg <asm1+37>` melakukan perbandingan signed integer antara nilai input dengan `0x6af` (1711 desimal).
   - Karena input $0xb70$ (2928 desimal) $> 0x6af$, lompatan bersyarat `jg` terpenuhi dan eksekusi berpindah ke offset `<+37>`.

2. **Divergensi Percabangan Lanjutan:**
   - Pada offset `<+37>`, dilakukan perbandingan kedua: `cmp DWORD PTR [ebp+0x8], 0xb70`.
   - Kondisi kesetaraan dicek dengan `jne <asm1+54>`. Karena input tepat bernilai `0xb70`, lompatan `jne` tidak diambil (fall-through).
   - Jalur eksekusi memasuki blok `<+46>`:
     - `mov eax, DWORD PTR [ebp+0x8]` $\implies$ `eax = 0xb70`
     - `sub eax, 0x17` $\implies$ `0xb70 - 0x17 = 0xb59`
     - `jmp <asm1+60>` $\implies$ Epilog fungsi (`pop ebp; ret`).

---

## Rekonstruksi & Verifikasi Eksekusi
1. **Perhitungan Manual:**
   $$0xb70 - 0x17 = 2928 - 23 = 2905 = \text{0xb59}$$

2. **Eksekusi Biner Native 32-bit:**

## Takeaway Kompetensi LKS & Mitigasi Defensif
- **Takeaway LKS:** Pengenalan struktur kontrol alur program (control flow graph / CFG) dari instruksi perbandingan (`cmp`) dan lompatan bersyarat (`jg`, `jne`, `jl`, `je`) adalah fondasi dasar dalam analisis malware dan pemetaan alur validasi lisensi perangkat lunak.
- **Mitigasi Defensif:** Dalam implementasi proteksi perangkat lunak anti-tamper, perbandingan statis linier mudah dibypass melalui dynamic patching. Disarankan menerapkan flattening control flow (OLLVM) atau kriptografi berbasis whitebox untuk mengaburkan relasi percabangan sensitif.
